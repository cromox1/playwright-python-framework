Q = How to make that videos and traces are only kept when a test fails.


Yes! This is actually the approach used in many enterprise Playwright frameworks. The idea is:

Always record the video and trace during the test.
After the test finishes, check whether it passed or failed.
If it passed, delete the video and trace.
If it failed, keep them.

This is much simpler than trying to decide beforehand.

Step 1: Create a context fixture

In conftest.py:

import os
from datetime import datetime
import pytest
from playwright.sync_api import sync_playwright


@pytest.fixture
def page(request):

    with sync_playwright() as p:

        browser = p.chromium.launch(headless=False)

        context = browser.new_context(
            record_video_dir="videos"
        )

        context.tracing.start(
            screenshots=True,
            snapshots=True,
            sources=True
        )

        page = context.new_page()

        # Make context available to hooks
        request.node.context = context

        yield page

        context.close()
        browser.close()
Step 2: Check whether the test passed or failed

Still in conftest.py:

@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):

    outcome = yield
    report = outcome.get_result()

    if report.when == "call":
        item.rep_call = report

Now every test knows whether it passed or failed.

Step 3: Save the trace only when the test fails

Back in your fixture, after yield:

yield page

timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")

trace_name = f"traces/{request.node.name}_{timestamp}.zip"

if request.node.rep_call.failed:

    os.makedirs("traces", exist_ok=True)

    context.tracing.stop(path=trace_name)

else:

    context.tracing.stop()

If the test passes:

No trace file is created.

If it fails:

traces/
    test_login_20260806_190021.zip
Step 4: Keep the video only on failure

After stopping the trace:

video = page.video

context.close()

if not request.node.rep_call.failed:

    if video:
        os.remove(video.path())

If the test passes:

videos/

will be empty.

If it fails:

videos/
    6d5a72b4-4f0e.webm

will remain.

Step 5: Screenshot only on failure

You already have something similar:

if report.when == "call" and report.failed:

    page = item.funcargs.get("page")

    if page:

        page.screenshot(
            path=f"screenshots/{item.name}.png",
            full_page=True
        )
Final behaviour

Suppose you run 100 tests.

95 PASS
No screenshot

No trace

No video
5 FAIL
Screenshot ✔

Trace ✔

Video ✔

Exactly what most enterprise teams want.

One small improvement

Instead of deleting successful videos manually, Playwright provides a cleaner API. After the context is closed, you can use:

video = page.video
context.close()

if video and not request.node.rep_call.failed:
    video.delete()

video.delete() is preferable to os.remove(video.path()) because it uses Playwright's API and avoids issues if the file location changes.

My suggestion

Your framework is now at a stage where it's worth organizing it into dedicated modules rather than keeping everything in conftest.py. For example:

core/
├── browser_manager.py
├── screenshot_manager.py
├── trace_manager.py
├── video_manager.py
├── logger.py
└── config.py

Then conftest.py becomes just fixtures and hooks (around 30–40 lines), while each manager has a single responsibility. This is a common structure in enterprise QA automation frameworks and will make your GitHub project look much more polished. It also makes it easier to explain your design decisions during interviews.
