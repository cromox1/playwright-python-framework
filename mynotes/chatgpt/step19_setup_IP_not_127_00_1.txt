Q = can I set the ipaddress as my laptop ip ('192.168.1.9') rather than '127.0.0.1' in the 'app/app.py' 

Yes, you can use your laptop's LAN IP 192.168.1.9 instead of 127.0.0.1.

Change the bottom of app/app.py from:

app.run(
    host="127.0.0.1",
    port=5000,
    debug=True
)

to:

app.run(
    host="192.168.1.9",
    port=5000,
    debug=True
)

Then start it:

python app/app.py

You should be able to access it from your laptop at:

http://192.168.1.9:5000
But there's an even better option

If your intention is to make the Flask application accessible from other devices on your home network, use:

app.run(
    host="0.0.0.0",
    port=5000,
    debug=True
)

Then:

On your laptop: http://127.0.0.1:5000
Using your laptop's LAN IP: http://192.168.1.9:5000
From another device on the same network: http://192.168.1.9:5000

0.0.0.0 means Flask listens on all network interfaces.

For your Playwright project

I'd actually recommend 0.0.0.0:

if __name__ == "__main__":

    with app.app_context():
        db.create_all()

    app.run(
        host="0.0.0.0",
        port=5000,
        debug=True
    )

And in your Playwright tests, use:

BASE_URL = "http://192.168.1.9:5000"

rather than hard-coding the URL throughout your tests.

For example:

page.goto(f"{BASE_URL}/login")

This will also make it easier later if you move the Flask SUT to another machine or run it inside Docker.



Q = Where should I put the 'BASE_URL' setting?


For your current project, I recommend putting BASE_URL in a configuration file, rather than directly inside each test or Page Object.

Since you already have a utils/ directory, a clean structure would be:

playwright-python-framework/
│
├── app/
├── tests/
│   ├── ui/
│   └── api/
│
├── pages/
├── utils/
│   └── config.py       ← BASE_URL here
│
├── data/
├── reports/
├── screenshots/
├── videos/
├── traces/
│
├── conftest.py
└── pytest.ini
1. Create utils/config.py
BASE_URL = "http://192.168.1.9:5000"
2. Use it in your Page Object

For example, pages/login_page.py:

from utils.config import BASE_URL


class LoginPage:

    def __init__(self, page):
        self.page = page

        self.username = page.locator("#username")
        self.password = page.locator("#password")
        self.login_button = page.locator("#login-button")
        self.login_error = page.locator("#login-error")

    def open(self):
        self.page.goto(f"{BASE_URL}/login")

    def login(self, username, password):
        self.username.fill(username)
        self.password.fill(password)
        self.login_button.click()

    def get_error_message(self):
        return self.login_error.text_content()
3. Use the same setting for API tests

For example:

from utils.config import BASE_URL


def test_get_users(api_request):

    response = api_request.get(
        f"{BASE_URL}/api/users"
    )

    assert response.status == 200

And:

def test_valid_login(api_request):

    response = api_request.post(
        f"{BASE_URL}/api/login",
        data={
            "username": "testuser",
            "password": "Password123"
        }
    )

    assert response.status == 200
Why this is better

Instead of having this everywhere:

http://192.168.1.9:5000

you only have it once:

BASE_URL = "http://192.168.1.9:5000"

If your Flask application later moves to another machine:

BASE_URL = "http://192.168.1.20:5000"

you only change one file.

Even better for your portfolio

Eventually, I'd move BASE_URL into an environment variable:

BASE_URL=http://192.168.1.9:5000

Then your same Playwright framework can run against:

DEV
QA
STAGING

without changing the test code. That's a useful CI/CD and enterprise QA practice to demonstrate in your GitHub project.
