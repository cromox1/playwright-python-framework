Q = context.tracing.stop ... is it before of after context.close()?


Good question. context.tracing.stop() must be called before context.close().

The reason is that once you call:

context.close()

the browser context is destroyed. After that, Playwright cannot save the trace, so calling context.tracing.stop() would either fail or produce an incomplete trace.

The correct order is:

yield page

# Save the trace
context.tracing.stop(path="traces/trace.zip")

# Then close the context
context.close()

# Finally close the browser
browser.close()
Complete example
import pytest
from playwright.sync_api import sync_playwright


@pytest.fixture
def page():
    with sync_playwright() as p:

        browser = p.chromium.launch(headless=False)

        context = browser.new_context(
            record_video_dir="videos/"
        )

        context.tracing.start(
            screenshots=True,
            snapshots=True,
            sources=True
        )

        page = context.new_page()

        yield page

        # Save trace first
        context.tracing.stop(
            path="traces/trace.zip"
        )

        # Then close context
        context.close()

        # Finally close browser
        browser.close()
One improvement

If you always save to:

traces/trace.zip

each test will overwrite the previous trace.

A better approach is to save a unique trace for each test using the test name and a timestamp.

For example:

from datetime import datetime

timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")

trace_name = f"traces/{request.node.name}_{timestamp}.zip"

context.tracing.stop(path=trace_name)

This produces:

traces/
├── test_login_20260806_145210.zip
├── test_search_20260806_145455.zip
└── test_checkout_20260806_145803.zip

This is much closer to how enterprise automation frameworks organize artifacts and makes it much easier to investigate failures.
