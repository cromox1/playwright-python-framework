Q = how to make a failed test that have video and tracing in it


The easiest way is to intentionally make an assertion fail after navigating to a page. Since the test runs normally before failing, Playwright will still generate the video, trace, and (if you implemented it) the failure screenshot.

Method 1 (Recommended)
def test_login(page):

    page.goto("https://the-internet.herokuapp.com/login")

    # Force the test to fail
    assert False, "Intentional failure for testing"

After running:

pytest

You should get:

videos/
    test_login.webm

traces/
    test_login_20260806_171500.zip

screenshots/
    test_login_20260806_171500.png
Method 2 (Fail on a wrong assertion)
def test_login(page):

    page.goto("https://the-internet.herokuapp.com/login")

    assert page.title() == "Google"

The actual title is something like:

The Internet

so the assertion fails.

Method 3 (Fail after logging in)

This is more realistic.

def test_login(page):

    page.goto("https://the-internet.herokuapp.com/login")

    page.fill("#username", "tomsmith")
    page.fill("#password", "SuperSecretPassword!")
    page.click("button[type='submit']")

    # Intentionally wrong expectation
    assert "logout" in page.url

The login succeeds, but the assertion fails, giving you a trace and video of the complete workflow.

Verify your trace and video
Video

Check:

videos/

You should see a .webm file.

Trace

Check:

traces/

You should see a .zip file.

To open the trace:

playwright show-trace traces/test_login_20260806_171500.zip

It opens Playwright Trace Viewer, where you can:

▶ Replay the test
📷 View screenshots at each step
🌐 Inspect network requests
📜 See console logs
⏱ Review timing information
🔍 Inspect the DOM at every action
One improvement to your framework

At the moment, your fixture likely saves a trace for every test. In enterprise frameworks, traces (and often videos) are usually saved only when a test fails. This keeps the artifact folders much smaller and makes failures easier to investigate.

If you'd like, I can show you how to configure your Playwright framework so that:

✅ 
Screenshots are saved only on failure
✅ 
Videos are kept only on failure
✅ 
Trace files are saved only on failure

That's the approach commonly used in production Playwright frameworks and is a nice touch for your GitHub project.
