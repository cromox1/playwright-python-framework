Q = Where to add 'context = browser.new_context' ? is it in conftest.py

Yes, exactly. browser.new_context() belongs in conftest.py, because the browser context is something you usually create once per test (or per test session) and then provide to your tests via a fixture.

The flow is:

pytest
   ↓
conftest.py
   ↓
Launch Browser
   ↓
Create Browser Context
   ↓
Create Page
   ↓
Run Test
   ↓
Take Screenshot/Video/Trace if Failed
   ↓
Close Context
   ↓
Close Browser
Basic version
import pytest
from playwright.sync_api import sync_playwright


@pytest.fixture
def page():

    with sync_playwright() as p:

        browser = p.chromium.launch(headless=False)

        context = browser.new_context()

        page = context.new_page()

        yield page

        context.close()

        browser.close()

Your test remains simple:

def test_login(page):

    page.goto("https://the-internet.herokuapp.com/login")

    ...
If you want automatic Video Recording

This is where new_context() becomes very useful.

context = browser.new_context(
    record_video_dir="videos/"
)

Every test will now produce a video.

If you want Trace Recording
context = browser.new_context()

context.tracing.start(
    screenshots=True,
    snapshots=True,
    sources=True
)

After the test:

context.tracing.stop(
    path="trace.zip"
)
If you want Screenshot on Failure

Your fixture becomes:

@pytest.fixture
def page():

    with sync_playwright() as p:

        browser = p.chromium.launch(headless=False)

        context = browser.new_context()

        page = context.new_page()

        yield page

        context.close()

        browser.close()

Then pytest_runtest_makereport() (also in conftest.py) will capture the screenshot when a test fails.

My recommended enterprise version

Eventually, your conftest.py might look like this:

conftest.py

├── Browser Fixture
├── Context Fixture
├── Page Fixture
├── Screenshot on Failure
├── Video Recording
├── Trace Recording
├── Logging
├── HTML Report Configuration
└── Pytest Hooks

Instead of one large fixture, you separate them:

@pytest.fixture
def browser():
    ...

@pytest.fixture
def context(browser):
    ...

@pytest.fixture
def page(context):
    ...

This approach is more modular and easier to maintain, and it's commonly used in enterprise Playwright frameworks.
