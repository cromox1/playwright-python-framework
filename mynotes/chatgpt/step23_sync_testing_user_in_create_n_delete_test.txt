Q = I want to synchronize the testing user in test_create_user_api.py & test_delete_user_api.py, but I don't want to put it into those 2 files. Should I put it into utils/config.py ?


Yes — but I wouldn't put the test user directly in utils/config.py.

config.py is better for things like:

BASE_URL = "http://192.168.1.9:5000"

For shared test data, I'd create a separate file such as:

playwright-python-framework/
│
├── utils/
│   ├── config.py
│   └── test_data.py       ← shared test users
│
├── tests/
│   └── api/
│       ├── test_create_user_api.py
│       └── test_delete_user_api.py
utils/test_data.py

For example:

TEST_USER = {
    "username": "automationuser",
    "password": "Password123",
    "email": "automation@example.com"
}

Then in test_create_user_api.py:

from utils.test_data import TEST_USER


def test_create_user(api_request):

    response = api_request.post(
        f"{BASE_URL}/api/users",
        data=TEST_USER
    )

    assert response.status == 201

    data = response.json()

    assert data["user"]["username"] == TEST_USER["username"]

And in test_delete_user_api.py, you can refer to the same username/email:

from utils.test_data import TEST_USER
However, there's an important issue

If your intention is:

Create automationuser in test_create_user_api.py, then delete that exact newly created user in test_delete_user_api.py.

Then simply sharing TEST_USER isn't enough.

For example:

test_create_user_api.py
        ↓
creates automationuser
        ↓
database assigns ID = 5
        ↓
test_delete_user_api.py
        ↓
needs ID = 5

You shouldn't hard-code 5.

For this situation, I'd use a pytest fixture that creates the user and returns its ID. For example:

@pytest.fixture
def created_user(api_request):

    response = api_request.post(
        f"{BASE_URL}/api/users",
        data=TEST_USER
    )

    assert response.status == 201

    return response.json()["user"]

Then:

def test_delete_user(api_request, created_user):

    user_id = created_user["id"]

    response = api_request.delete(
        f"{BASE_URL}/api/users/{user_id}"
    )

    assert response.status == 200

This is actually the approach I'd recommend for your Playwright GitHub framework.

So I'd separate your shared information like this:

utils/
├── config.py          # BASE_URL, environment settings
└── test_data.py       # usernames, passwords, test data

conftest.py            # reusable pytest fixtures

config.py → configuration
test_data.py → test data
conftest.py → reusable test setup/fixtures

That's a much cleaner architecture than putting everything into config.py.
