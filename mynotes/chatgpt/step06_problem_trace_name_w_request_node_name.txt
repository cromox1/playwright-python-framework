Q = this line :   trace_name = f"traces/{request.node.name}_{timestamp}.zip"     ... have problem with 'request.node.name'.... how to fix that


The problem is that request is not automatically available. You need to inject it as a PyTest fixture.

Solution 1 (Recommended)

Modify your fixture to accept request:

@pytest.fixture
def page(request):

Then you can use:

request.node.name

Example:

import pytest
from datetime import datetime
from playwright.sync_api import sync_playwright


@pytest.fixture
def page(request):

    with sync_playwright() as p:

        browser = p.chromium.launch(headless=False)

        context = browser.new_context()

        context.tracing.start(
            screenshots=True,
            snapshots=True,
            sources=True
        )

        page = context.new_page()

        yield page

        timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")

        trace_name = f"traces/{request.node.name}_{timestamp}.zip"

        context.tracing.stop(path=trace_name)

        context.close()

        browser.close()

Now if your test is

def test_login(page):
    ...

The trace file becomes

traces/test_login_20260806_171500.zip
Solution 2 (Even Better - Enterprise)

In enterprise frameworks, we usually separate the page fixture from trace handling.

Instead of putting this inside the fixture, we use a PyTest hook:

@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):

Then use

item.name

instead of

request.node.name

because item already represents the current test.

My recommendation

Since we're building your GitHub project to look enterprise-grade, I would actually avoid putting context.tracing.stop() inside the page fixture.

A better design is:

page() fixture → only creates and returns the page.
pytest_runtest_makereport() → handles screenshots.
Another fixture or hook → handles trace recording.
Another hook → handles logging.

This keeps each component focused on a single responsibility and is easier to maintain as your framework grows.
