That error is expected because api_request doesn't exist yet. In my previous example, I assumed you'd create an api_request fixture, but I didn't show it.

There are two ways to do API testing with Playwright.

Option 1 (Recommended - Enterprise)

Create an api_request fixture in conftest.py.

import pytest
from playwright.sync_api import sync_playwright


@pytest.fixture
def api_request():

    with sync_playwright() as p:

        request_context = p.request.new_context()

        yield request_context

        request_context.dispose()

Now your test will work:

def test_get_user(api_request):

    response = api_request.get(
        "https://reqres.in/api/users/2"
    )

    assert response.status == 200

    data = response.json()

    assert data["data"]["id"] == 2

Run:

pytest tests/api/
Option 2 (Simpler)

Don't use a fixture.

from playwright.sync_api import sync_playwright


def test_get_user():

    with sync_playwright() as p:

        request = p.request.new_context()

        response = request.get(
            "https://reqres.in/api/users/2"
        )

        assert response.status == 200

        request.dispose()

This works, but it's not ideal because every test creates its own request context.

My Recommendation

Since you're building this as an enterprise-style framework, I recommend keeping two separate fixtures in conftest.py:

@pytest.fixture
def page(...):
    ...

for UI automation, and

@pytest.fixture
def api_request():
    ...

for API automation.

Then your project structure becomes:

playwright-python-framework/
│
├── tests/
│   ├── ui/
│   │   ├── test_login.py
│   │   └── test_search.py
│   │
│   └── api/
│       ├── test_users_api.py
│       └── test_login_api.py
│
├── pages/
├── api/
├── utils/
├── conftest.py

This separation is common in enterprise frameworks because UI tests and API tests often have different setup and teardown requirements.

I have one suggestion

Since you're aiming to impress recruiters, I'd avoid using reqres.in as the long-term demo API. It's good for learning, but many candidates use it.

Instead, build a small Flask REST API with endpoints like:

POST /login
GET /users
POST /users
DELETE /users

Then automate those APIs with Playwright. That demonstrates not only API test automation skills, but also an understanding of REST API design. It's a stronger portfolio piece and gives you something more distinctive to discuss during interviews.
